# 家族配对统计与检查点回放审计

日期：2026-09-18。定位：PLOS Computational Biology 投稿准备中的内部证据审计。

## 结论

后续审计已恢复全部三个种子的历史指标：使用 Git 57f3f36 的历史 ESM2 forward 与历史评估 CLI 默认 batch 64，RMSE/MAE/Pearson 的最大绝对差异为 1.2e-7，小于冻结容差 1e-5。无需降级 PyTorch；计划中的旧版环境下载已取消。

历史结果可复现，但依赖历史序列填充实现及批量设置。不能将其当作当前修复后代码的成绩。历史和当前实现下，模型与 CataPro、UniKP 的差异均尚无明确统计支持；跨零区间不证明等效。

## 可复现性问题

冻结权重、原始数据和同源划分的 SHA256 校验通过；1,646 个测试样本的序列、底物、标签与导出表逐行一致。当前实现回放的指标与旧记录超过预先设定的 1e-5 容差，因此原定历史结果的配对分析停止，未放宽容差。

|种子|历史 RMSE|当前实现 RMSE|变化|
|---|---:|---:|---:|
|7|1.388023|1.393796|+0.005773|
|42|1.375439|1.379192|+0.003753|
|123|1.411404|1.413799|+0.002396|

已检查批量 32/4，并从 Git 提取历史 ESM2 forward 进行诊断。历史实现曾将 EOS 放在批量统一末尾，后续提交 37ece28 修复为每条序列单独 EOS。历史 forward 在这两个批量下仍未复现种子 7 的原指标，故不能认定这一修改是全部原因。历史检查点记录 PyTorch 2.11.0+cu128，当前 Windows 环境为 2.12.0+cu130；运行环境差异也仍待核验。

本轮没有修改生产模型、权重或历史指标。历史 forward 仅用于独立诊断进程。当前代码审计使用批量 4，三个预先固定的种子，不训练、不选择更好的检查点。它是旧权重在当前代码下的审计，不能替代按当前代码重新训练的正式实验。

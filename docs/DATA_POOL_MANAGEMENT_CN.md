# 数据池分层与增量管理

运行以下命令生成空间盘点、来源索引、变更队列及证据快照：

```powershell
python scripts\manage_data_pool.py
```

输出位于 `artifacts/data-pool-management/`：

- `report.md`：空间类别、来源层级和归档候选目录。
- `report.json`：内容相同的文件组、最大文件、变更或待审核来源、缺失文件及错误。
- `index.sqlite`：全部 `artifacts/` 和 `data/` 文件的大小、修改时间；证据文件另有 SHA256。
- `registry-current.json`：使用现有只读注册表逻辑重新核对当前 CSV 和审核契约，不覆盖历史注册表。
- `snapshots/<SHA256>.json`：时间池常规证据文件内容及协议、全局审核、v6 发布清单的身份。临时缓存和外部链接列为排除项；已有快照不覆盖。

来源目录分为接受来源证据、待审核及归档候选三层。接受来源内仍可能包含排除行，来源层级不等于逐行接受。未注册来源一律待审核。正式准入、全局家族计数及评分许可继续由原协议与审核程序决定。

日常重复运行复用大小和纳秒修改时间未变的哈希，优先计算时间池证据。默认每轮最多读取 1024 MiB；超过预算的文件明确列为待计算。全部时间池常规证据文件都有哈希且扫描无错误时才生成证据快照。索引自身不计入被扫描的数据量。WSL/NTFS 链接仅记录路径和元数据，不读取其目标；`cluster_tmp`、Python 缓存和下载缓存单独归类，不进入证据快照。

`review_queue` 包含新增、变更、删除、待审核或哈希不完整的来源；协议或控制文件变更也将触发复核。该队列是审查提示，不自动执行生物学审核。首次运行建立基线；之后来源证据变更的复核标记持续保留，不能靠重复扫描自动消失。完成实际证据审核后，用 `--reviewed-source <来源目录名>` 明确确认；未解决或哈希不完整的来源不能确认。当前注册表的轻量契约核对每次仍会执行。

正式使用证据前，可增加预算并强制重新计算哈希，防止同大小、同修改时间的内容变更被缓存跳过：

```powershell
python scripts\manage_data_pool.py --verify-hashes --hash-budget-mib 4096
```

证据快照仅记录内容身份，不是训练集或测试集冻结许可。评分前仍需按 `DATA_ARRIVAL_RUNBOOK.md` 通过全部准入门槛并绑定记录清单、拆分和模型身份。若预算仍不足，先补齐哈希，不把不完整报告当成全量内容校验。

相同文件哈希仅生成重复候选清单；不合并不同条件的测量，不删去原始附件。归档候选是原审核结论为零接受的来源，保留原路径以免破坏引用和冻结证据。下载缓存与运行环境分开统计；清理缓存之前先确认对应任务已停止。环境、权重、发布归档及历史证据不自动删除。

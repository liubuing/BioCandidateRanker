## 恢复机制

新增单成员执行入口，每轮验证与选模结束后保存原子替换的 `recovery.pt`，包括：当前模型、优化器、学习率调度器、最佳分数及对应最佳检查点、迭代数、Torch/NumPy/Python 随机状态和训练采样器随机状态。恢复时回到最后完整轮次，中途未保存的部分重新执行。

仅对本项目冻结身份一致的状态执行恢复，使用 `weights_only=True`。NumPy 数值被转换为安全基础类型，最佳检查点以 uint8 张量嵌入，避免依赖旧版 PyTorch 不支持的 pickle 字节编码。恢复不覆盖已保留的历史运行。

队列持有进程文件锁，防止同一目录被重复执行。已完成成员按校验值跳过，未完成成员从自己的轮次状态恢复。机器关闭后仍需要重新启动队列，不能宣称训练可以跨关机连续运行。

## 随机种子修订

尚未完成的成员改为预先固定的独立初始化种子：成员 0 使用组种子 s，成员 j>0 使用 1000s+j；组种子为 7、42、123。数据采样种子使用组种子，各成员独立初始化采样器。

这是对原串行集成共享随机流的明确修订，不能声称完全复现原随机轨迹。保留的首成员仍是 s=7、j=0，原初始化和采样种子均为 7；其他配置、样本、epoch 数及验证选模规则不变。此修订不基于测试结果或成员性能进行选择。

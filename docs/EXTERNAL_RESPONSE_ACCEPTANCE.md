# External Response Acceptance

Responses are evidence only after their identity and authority are recorded. Do not mark a
request complete from an informal promise.

## Intake

- Preserve the original message or repository response and attachments.
- Record sender identity, role, timestamp, message reference, and delivery path.
- Hash every received file before opening or normalizing it.
- Confirm that the respondent controls the requested data or permission.
- Treat links returning HTTP 404 as skipped and unresolved; do not retry in the same cycle.

## Purdue Cdc14

Accept only if the delivered files include the original measurement workbooks or equivalent
row-level exports and enough construct/assay metadata to apply the frozen temporal protocol.
CC0 coverage must be explicit for the delivered measurement files.

## SABIO-RK

Permission must explicitly address model training, normalized derived rows, checkpoints,
aggregate reporting, and sharing boundaries. Data remain blocked if exact final assayed
chains cannot be established per selected entry.

## yeast-GEM Flux

Accept only an authoritative data dictionary or source mapping that resolves units,
normalization, sign, strain, condition, replicate, uncertainty, method, citation, and model
reaction mapping. Do not infer these fields from column values.

## Prospective Campaign

The actual named custodian must complete and approve the handoff. Numeric labels must remain
outside the modeling workspace until the blind prediction deposit is accepted. A recipient
identified only by the modeling team cannot self-certify independent custody without
supporting organizational or operational evidence.

After an accepted delivery, follow `docs/DATA_ARRIVAL_RUNBOOK.md`.
